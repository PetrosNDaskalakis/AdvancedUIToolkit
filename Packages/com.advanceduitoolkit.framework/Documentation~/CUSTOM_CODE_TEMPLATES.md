# Custom binding code templates

The Binding Workspace supports optional **compilable C# examples** for controlling the shape and formatting of generated binding scripts. No third-party parsing packages are needed.

## Create a template

1. Import the `Code Generation Template` sample from Unity Package Manager, or copy `Samples~/CodeGeneration/ExampleScript.cs` into `Assets`.
2. Keep one `namespace`, one class implementing `IUIBindings` and the public `Initialize(UIBindingRoot root)` method.
3. Within the class, add a standalone `// <ADVANCEDUITOOLKIT:PROPERTIES>` comment.
4. Within `Initialize`, add a standalone `// <ADVANCEDUITOOLKIT:ASSIGNMENTS>` comment.
5. Customize the example's indentation, blank lines, XML documentation, import directives and helper code.
6. Select your UI root in **Tools > Advanced UI Toolkit > Binder**, assign the **Example Script** asset and generate.
7. Optional: click **Set Default** to apply this style automatically to all newly configured roots.

The script is a **template only**: the generator reads it and never edits its contents. It replaces the namespace and the example class name, expands the two markers, and prepends `// <auto-generated />` to the output. Output is always in the consuming project's `Assets` directory.

## Example

```csharp
using System;
using AdvancedUIToolkit;

namespace Example.Template
{
    /// <summary>Template controlling my team's binding layout.</summary>
    public sealed class ExampleScript : IUIBindings
    {
        // <ADVANCEDUITOOLKIT:PROPERTIES>

        /// <summary>Connects references from the UI root.</summary>
        /// <param name="root">Serialized binding registry.</param>
        public void Initialize(UIBindingRoot root)
        {
            if (root == null) throw new ArgumentNullException(nameof(root));
            // <ADVANCEDUITOOLKIT:ASSIGNMENTS>
        }
    }
}
```

For `BTN_Fire`, it will generate a documented `Button Fire` property and the corresponding cached `root.Get<UnityEngine.UI.Button>("Fire")` assignment. The layout of the rest of the example remains intact.

## Validation and safeguards

- Markers must each appear exactly once and on their own line.
- The source must be a C# asset under `Assets` or `Packages`, not an existing generated file.
- Namespace and class declarations must be unambiguous.
- Invalid templates block manual generation.
- The path is saved per `UIBindingRoot`, so each screen can use a different coding style.
- Modifying an example requires manual regeneration before unattended generation resumes.
- This feature is intentionally limited to insertion-point templates; it does **not** attempt to rewrite arbitrary methods or interpret JSON schemas.

## Current limitations

The template must compile normally as a C# class before being used. A helper method in the template can be copied into generated code, but the template itself also remains in the project. Avoid non-static dependencies on generated members within the original template. For complex formats beyond two insertion points, extend the template engine rather than depending on fragile text replacement.

## v0.9.6: Custom XML documentation

Optionally add the following **single-line C# comment** to your `ExampleScript.cs`, before the properties marker:

```csharp
// <ADVANCEDUITOOLKIT:PROPERTY_DOC>Reference to {name} ({type}) on {hierarchy}.
// <ADVANCEDUITOOLKIT:PROPERTIES>
```

Available placeholders: `{name}` (generated C# property), `{hierarchy}` (name-derived binding key), and `{type}` (fully qualified Unity component type). XML-special characters in descriptions are escaped automatically. Use the directive at most once. Without it, the old v0.9.5 property documentation format remains unchanged.

You can review proposed output using **Binder > Preview Generated C#** without writing source code or triggering a Unity compile. Template edits require manual regeneration to keep the old generation safety checks intact.
